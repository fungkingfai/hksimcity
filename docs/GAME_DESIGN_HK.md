## 0. 遊戲概述與設計支柱

### 0.1 一句話

> **由中環一個小社區開始，鋪路、劃區、起公共設施、過海，讓維港兩岸自己生長成一個城市；你可以走進每一棟樓，看看香港人怎樣生活。**

### 0.3 設計支柱（所有取捨以此判斷）

1. **維港是主角，不是背景**：兩岸分治、過海稀缺、隧道／渡輪／港鐵各有代價；颱風會令渡輪停航、露天段停駛。這是《維港之城》與所有同類遊戲的分野（R-HAR-1、R-CS-1）。
2. **土地稀缺是核心壓力**：山多平地少、填海地是高價地段、公屋排隊愈來愈長；玩家永遠在「起樓、起公屋、賣地、起公園」之間取捨（R-GEO-1、R-LAND-3）。
3. **香港人的生活方式就是制度**：茶餐廳、街市、便利店、酒樓、叮叮、天星小輪、霓虹招牌、山頂纜車——不是裝飾，而是食物供應、就業、車費收入、觀光收入與幸福度（R-SOC-1、R-PEAK-1）。
4. **交通是經濟系統**：站點＝通勤服務＋車費收入＋就業；交通慢＝物流慢＝零售缺貨＝幸福跌；颱風令交通停頓（R-MTR-1、R-BUS-1、R-TY-4）。
5. **天氣有後果，而且有預警**：1 號／3 號風球準備、**8 號風球停工停課**；黑雨、酷熱、寒潮、大霧、大帽山結霜各有不同影響（R-TY-1、R-CLIM-1）。
6. **原因要說人話**：任何「數字不好」都必須能追溯到一個玩家看得懂的原因（缺路、缺電、缺水、缺貨、塞車、稅太重、公屋排隊太長、颱風）。
7. **室內是特色而非負擔**：每一棟建築都能進去；室內要回答「這棟樓現在運作得好不好、裡面住著／工作著誰」——走進劏房看到一家四口住 8 平方米，比「幸福 42」更有力（R-SOC-1、R-CS-4）。
8. **霓虹港風但不浮誇**：深藍夜色＋霓虹光是視覺語言；文字、圖示、面板要清楚，任何時候玩家都知道下一步做什麼。
9. **分區自主**：玩家規劃土地用途與公共投資，樓宇由市場（開發商）按需求興建；成就感來自「我規劃了一個會自己生長的城市」，不是逐棟樓點擊。

## 1. 核心循環（分區版）

### 1.1 四層循環

| 層級 | 時間尺度 | 玩家在做什麼 | 系統結算 |
|---|---|---|---|
| **秒級** | 每幀 | 鋪路、刷分區、看需求條、看 hover 發展分數、擺公共設施 | 市民／車輛移動、分區色塊預覽、服務覆蓋計算 |
| **日級** | 30 秒（1×） | 看 RCI+F 需求條、補路、補區、補警／消／校／醫／交通 | **需求更新 → 自動開發（每日最多 5 棟）**、人口／就業／幸福／荒廢 |
| **月級** | 3.5 分鐘 | 看月報表、調稅率、賣地／煙花、規劃過海 | 稅收、支出、車費、服務收入、月報表 |
| **年級** | 42 分鐘 | 擴張新市鎮、過海發展、追成就 | 四季、颱風季、公屋輪候、地價上升 |

### 1.2 正回饋鏈

```
鋪路（自帶行人路） ─→ 劃住宅區 ─→ 開發商起唐樓／劏房 ─→ 人口↑ ─→ 勞動力↑
   ↑                                                        │
   │                                                        ↓
幸福↑ ←─ 公園／學校／醫院 ←─ 稅收＋車費 ←─ 商業區（便利店／茶餐廳／街市）←─ 需求↑
   │                                                        │
   │                                                        ↓
   └──────── 劃更多分區／起公共設施 ←──── 工業區提供職位＋貨物 ←── 農業區供食品
```

- **需求（RCI+F）**：`GameState.zoneDemand`（−1..1）；需求 ≥ `AUTO_DEVELOP.minDemand`（0.12）開發商才會起樓；負數＝供過於求、暫停開發。
- **發展分數（devScore 0–100）**：供電、供水、警、消、校、醫、交通、幸福、地價加權；決定可出哪一級建築（詳見 `ZONING_GAMEPLAY.md` §4）。
- **服務覆蓋**：既是 devScore 的輸入，也是市民幸福的來源；住了豪宅但無醫院，市民一樣會搬走。
- **土地**：600×600 共 360,000 格，分區格有限、地價隨發展上升、賣地可換一次性現金；自動建築全城上限 **1,200 棟**（每日 15 棟、每區 6 棟）。

### 1.3 前 10 分鐘教學腳本（預設「已有城鎮」；1× 速度）

| 時間 | 玩家動作 | 預期結果／教學提示 |
|---|---|---|
| 0:00–0:30 | 開局畫面選「**已有城鎮**」（推薦）；入場後見中環已有樓、有車、有需求條 | 知道「需求條 → 劃區 → 開發商起樓」 |
| 0:30–1:30 | 按 **L** 開分區色塊；按 **O/P** 試 minimap 導航；觀察四色分區與需求條 | 明白顏色＝分區、需求條＝市場訊號、大地圖可一鍵 overview |
| 1:30–3:00 | 在城市邊緣鋪 6–10 格路（$90,000–$150,000）；用「住宅區」刷 3×3（$10,800） | 1–3 日後開發商起唐樓／劏房，人口上升 |
| 3:00–4:30 | 刷商業區 2×3（$9,000）；看便利店／茶餐廳自動落成 | 商業需求被消化、街坊有嘢買 |
| 4:30–6:00 | 人口 90 解鎖公共屋邨；起**警署**（$1,800,000）或**消防局**（$1,700,000） | devScore 上升，可出更高級住宅 |
| 6:00–8:00 | 起**公園**（$350,000）／**學校**（$1,600,000）；擴工業區 | 幸福＋devScore 上升；工業區出工廈 |
| 8:00–10:00 | 人口 180 解鎖**港鐵站**；規劃過海（維港對岸）或起港鐵站 | 通勤改善、車費收入，為豪宅鋪路 |

> **Empty 模式差異（由零開始）**：**完全空地圖**——零道路、零建築、零分區、無地標／機場／貨櫃碼頭等任何人造構築物（只有自然地形、樹木、海面船隻）；$8,000,000、5 名市民（設計要求）；頭 3 分鐘先鋪 8 格路＋2×3 住宅區（$7,200）＋2×2 農業區（$2,800），靠劏房／唐樓／便利店／農田起步；公園（0 解鎖）優先，發電廠／水務要等人口 180／90。
> **設計檢查點**：10 分鐘內玩家應見過一次「需求不足／供應過剩」提示、一次「發展商建成 XX」log、一次公共設施提升 devScore 的變化。

### 1.4 玩家每 30 秒的決策清單

1. 現在哪一條需求最高？（住宅／商業／工業／農業）
2. 要唔要擴區？擴幾多格？劃喺邊？（近路、近現有服務、地價高）
3. 邊一項公共設施最缺？（電／水／警／消／校／醫／交通）→ 起完 devScore 會升
4. 要唔要拆舊樓（退款 30%）換高級建築？
5. 分區成本 vs 庫房：$1,200–$1,500/格，唔好一次過刷爆
6. 交通夠唔夠？（通勤 > 40 分鐘 → 幸福下降；巴士／電車／港鐵／渡輪）
7. 要唔要賣地？（$2,500,000 即時現金 vs 土地儲備）
8. 颱風／黑雨要來了嗎？（停航停駛、物流變慢、地盤停工）

1. **資料來源**：`src/world/hk-map-data.generated.ts`（由 `tools/build-hk-data.py` 從 CSDI／地政總署 DTM 5m＋342,233 個建築輪廓生成；下載 URL 與授權見 `REAL_GEO_DATA.md`）。

4. **可建地**：實測 **22.4%**（grass／urban／reclaimed／fertile／forest／hill）；水域 **75.6%**；山多平地少（hill 7.5%、mountain 1.7%）。**不再有** Round 3 的「補到 52% 可建」邏輯。

7. **empty**：`generateRealWorld({starterRoads:false})`；render `showcaseCity=false` → 唔顯示真實樓群／地標／機場／貨櫃碼頭；只有自然地形、樹木、海面船隻。

9. **地名／地標／區塊**：以真實座標放 label／landmark／region，LOD 見 §2.2；機場雙跑道、葵涌貨櫃碼頭按真實位置。

11. **海面**：地圖外圍加無邊海面 mesh，隱藏 600 邊界。
12. **驗收**：startup 解碼＋生成約 2.5–4 秒（boot screen）；starter overview ≤2.0M tris／≤550 calls；empty 1.032M tris／37 calls；地圖無穿崩邊界；舊 96×96／304×304 存檔拒絕。

| `materials` | 建材 | 工業 | 石礦場 12/日、貨櫃碼頭（少量） | 工廈投入；v1.1 建造材料 | 60 | ×1.2 | ❌ |

> ⚠️ **不要再新增 medicine／fuel／water／power 資源**：食水與電力在現行架構是 `UtilityDef`（覆蓋半徑＋容量），不是物流資源。這是與初版設計最大的簡化，所有 Agent 必須跟從。

### 4.2 生產鏈總圖

```
【本地生產】
  農田（食品 24/日）──────────────┐
  食品廠（食品 16/日；投入日用品 3）┤
  進口商行（日用品 10/日）────────┤
  貨櫃碼頭（日用品 45/日；進口）──┤──▶ 貨倉（600）──▶ 街市／便利店／超市／商場／茶餐廳／酒樓
  石礦場（建材 12/日）────────────┤                              │
  工廈（電子 6/日；投入建材 5）────┘                              ▼
                                                       市民（食品 0.5、日用品 0.2、消閒）
【公用設施】
  發電廠（半徑 22、容量 1,600）──▶ 全城電力覆蓋
  水務設施（半徑 18、容量 2,000）──▶ 全城食水覆蓋
```

- **早期（人口 < 30）**：無貨倉，農田／進口商行的貨由貨車**直送**零售點（街市／便利店／茶餐廳）——這是 Lead 定案的核心早期循環。
- **後期（人口 ≥ 30）**：貨倉成為緩衝；生產建築 → 貨倉 → 零售點；沒有貨倉時仍可直接配送，但庫存壓力大。
- **貨櫃碼頭（人口 300）**：取代進口商行成為日用品主要來源（45/日）；進口商行仍可保留作備用／舊區供應。

### 4.3 公用設施：電力與食水（`UtilityDef`）

| 設施 | key | 半徑 | 容量（人口單位） | 維護/月 | 說明 |
|---|---|---|---|---|---|
| 發電廠 | `powerPlant` | 22 格 | 1,600 | $50,000 | 全城電力；覆蓋不足 → 停電 |
| 水務設施 | `waterworks` | 18 格 | 2,000 | $22,000 | 全城食水；覆蓋不足 → 缺水 |

```
計算（每日一次，寫入 stats）：
  powerCoveredPop = Σ(半徑 22 內住宅人口，取覆蓋住宅；多廠不重複計)
  waterCoveredPop = Σ(半徑 18 內住宅人口，取覆蓋住宅；多廠不重複計)
  powerCoverage = clamp(powerCoveredPop / max(1, population), 0, 1)
  waterCoverage = clamp(waterCoveredPop / max(1, population), 0, 1)

效果：
  powerCoverage < 1 → 未被覆蓋的建築效率 ×0.5（工廠停產、服務暫停）；UI「停電」
  waterCoverage < 1 → 未被覆蓋的住戶幸福 −6；工業 ×0.7；UI「缺水」
  兩者都會令 stats 顯示覆蓋率（0..1），UI 必須以百分比顯示
```

- 公用設施**不需要道路運輸**、不消耗物流資源；發電廠／水務設施只需臨路（config `needsRoad:true`），水務設施不需臨水（config 未設 `needsWater`）。
- 覆蓋率隨人口增長會下降 → 玩家要按人口加建（每廠 ≈ 1,600／2,000 人）。
- 污染：發電廠半徑 6 格內住宅幸福 −4（設計值）；半徑 3 格內不可建學校／醫院（placement 拒絕）。

### 4.4 貨櫃碼頭與進口（設定對齊）

- `containerPort` 每日生產 **日用品 45**（象徵進口；`weatherBonus: storm 0.1, rain 0.85`）；需人口 300、$8,000,000、臨水＋臨路、只可建於西岸港口。
- 碼頭**本身不產生現金**；它的價值是「穩定日用品供應」→ 零售營業 → 利得稅與幸福。
- **出口（v1.1）**：電子產品過剩時可出口（`electronics` 參考價 $900）；v1 不做出口收入，避免與 config 衝突。
- 進口商行（人口 30、$240,000）是早期日用品來源（10/日），可與貨櫃碼頭並存。

### 4.5 物流：貨車（`Cart`）派遣

| 規則 | 內容 |
|---|---|
| 檢查頻率 | 每 **30 遊戲分鐘**（@1× 約 0.625 真實秒）掃描一次 |
| 派遣條件 | 生產建築 `connected`、有工人、本地庫存 ≥ 10 |
| 目的地優先 | ① 最近的貨倉（容量夠）→ ② 若無貨倉或貨倉滿，直接送到**缺貨的零售點**（同資源） |
| 單趟數量 | `min(TRUCK_CAPACITY=60, 本地庫存)`；載具 `vehicleKind` 貨車／客貨車 |
| 上限 | 同時最多 **60 台**；超過排隊，優先最舊庫存 |
| 路徑 | `findPathBetweenBuildings`；無路徑 → 不派遣、提示「道路未接通」 |
| 移動 | 沿道路，速度受天氣 `WEATHER_EFFECT.move` 影響（颱風 ×0.35、黑雨較慢） |
| 抵達 | 轉移貨物 → `pickup`→`deliver` → `done`；計入 `stats.goodsInTransit` |
| 容量不足 | 目的地全滿 → 不派遣；生產建築本地暫存 60 滿 → 停產（壓力） |
| 拆除 | 拆除建築時移除相關 carts（placement 負責） |

## 5. 市民與需求系統

### 5.1 市民生命週期

| 階段 | 規則 | 數值建議 |
|---|---|---|
| 開局市民 | **已有城鎮**模式經 warm-up（10 日）自然遷入至約 146 人（QA 實測）；**由零開始**模式按設計生成 **5 名**成年人（18–45 歲），無家、失業，在中環 spawn 附近等待（⚠️ 見 §13.3 #1：實作待補 seeding） | 🔧 `population.ts`；spawn 設計 (51.4,59.4)，格座標約 (259,299) |
| 遷入 | 每棟住宅每日檢查空位；平均幸福 ≥ 50 時，每個空位有 `p = clamp((幸福-45)/100, 0, 0.40)` 機率遷入；無家者優先 | 🔧 每日最多遷入 `4 + floor(pop/40)` 人 |
| 出生 | 幸福 ≥ 65 且住宅有空位：每日每 100 居民約 0.4 名新生 | 🔧 新生兒直接以 18 歲青年出現（遊戲年僅 84 日） |
| 死亡 | 每日機率 `0.0004 + max(0, age-60) × 0.00018`；醫院覆蓋 ×0.7，無醫院 ×1.4；寒冷／酷熱警告期間 65+ ×1.5 | 🔧 平均壽命 70～80 遊戲歲 |
| 遷出 | 幸福 < 25 連續 3 日 → 每日 10% 機率 1 人搬走；無家者 5 日後離開；颱風後 3 日內 ×1.5 | 🔧 遷出理由寫入 log |
| 上限 | `citizens.length ≤ 1600`（`sim/population.ts` 的 `MAX_POPULATION`） | 住宅容量不足時停止遷入；人口里程碑至 1,600 |

- **年齡層**：0–15 兒童（不工作）、16–64 勞動人口、65+ 長者（不工作、醫療需求高）。
- **薪金**：受僱市民 `salary = BASE_MONTHLY_SALARY = $18,000`（config）；每月生活開支 `BASE_LIVING_COST = $6,000`；`citizen.money` 用於購物與儲蓄，不直接進國庫。
- **住戶**：以 `homeId` 分組，每戶約 3 人；用於公屋輪候與統計。

### 5.2 三大需求（食品／日用品／消閒）

`CitizenNeeds`（已定稿：`food`／`goods`／`leisure`，0..100），每日結算：

| 需求 | 滿足條件 | 每日變化 | 長期不足後果 |
|---|---|---|---|
| `food` 食品 | 住宅在街市／超市／便利店半徑內，且該店有食品庫存 → 滿足；否則全城食品庫存 > 0 → 部分滿足（自家煮食） | 滿足 +14；部分 +7；不足 **−20** | 連續 2 日不足 → toast「屋企冇飯開」；全城無食品 → 饑荒（幸福 −10/日、遷出加速） |
| `goods` 日用品 | 住宅在便利店／街市／超市／商場半徑內，且貨架有日用品 → 滿足 | 滿足 +10；否則 **−14** | 連續 5 日不足 → 「生活質素下降」事件 |
| `leisure` 消閒 | 住宅在公園／海濱長廊／商場／酒樓半徑內 → 滿足（同類型取最近一棟，不疊加） | 滿足 +7；否則 **−9** | 影響幸福；< 35 歲額外 −3 |

- 市民每日消耗：**食品 0.5／人、日用品 0.2／人**（Lead 定案）；消耗由零售點貨架扣除。
- 零售點收入 = `service.incomePerDay` × 7（月）；收入與「有貨」掛鉤（無貨 → util 下跌，見 §7）。

### 5.3 幸福度公式

```
base = 45
foodScore    = needs.food    × 0.22      // 0..22
goodsScore   = needs.goods   × 0.15      // 0..15
leisureScore = needs.leisure × 0.10      // 0..10

housingScore = 劏房 −8、唐樓 0、公共屋邨 +3、居屋苑 +5、私人屋苑 +6、豪宅 +8
               擠迫 residents > housing × 1.2 → −5；無家 −15
commutePenalty = clamp((stats.avgCommute − 20) × 0.45, 0, 12)
unemploymentPen = (workId < 0 && 16≤age≤64) ? 8 : 0
taxPenalty = salaryTaxRate×100×0.30 + profitTaxRate×100×0.10 + ratesRate×100×0.20
             // 預設 15%／16.5%／5% → −4.5 −1.65 −1.0 ≈ −7.15
serviceBonus = 半徑內服務加成（每類型取最近一棟，上限 20）
               公園 +5、海濱 +4、餐飲 +5、學校 +6、醫院 +8、警署 +4、消防 +3
utilityPenalty = (1 − stats.powerCoverage) × 8 + (1 − stats.waterCoverage) × 6
weatherBonus = WEATHER_EFFECT[weather].happiness   // 晴 +2、陰 0、雨 −1、霧 −2、雪 −6、颱風 −8
typhoonPenalty = (stats.typhoonSignal === 8) ? 2 : 0
festivalBoost = max(0, 12 − (totalDays − finance.lastFestivalDay))
bankruptcyPen = treasury < 0 ? 5 : 0
prhPenalty = 公屋輪候 > 5 年 → 3（見 §5.5）

target = clamp(base + foodScore + goodsScore + leisureScore + housingScore
             − commutePenalty − unemploymentPen − taxPenalty + serviceBonus
             − utilityPenalty + weatherBonus − typhoonPenalty + festivalBoost
             − bankruptcyPen − prhPenalty, 0, 100)

happiness += clamp(target − happiness, −6, +4)   // 每日平滑
```

| 幸福 | 稱呼 | 顏色 | 行為 |
|---|---|---|---|
| 70–100 | 安居樂業 | 霓虹青綠 | 遷入快、出生率上升 |
| 40–69 | 生活逼人 | 霓虹黃 | 穩定遷入 |
| 25–39 | 民怨漸生 | 霓虹橙 | 遷入停滯、偶有遷出 |
| 0–24 | 民不聊生 | 霓虹紅 | 大量遷出、事件風險 |

### 5.4 行為狀態機

```
home ──(07:00 起床)──▶ walking ──到達──▶ working
  ▲                                        │
  │                          (18:00 下班，隨機購物／消閒)
  │                                        ▼
  └──────────── home ◀──到達── shopping／leisure ◀── walking
idle：無家、失業、路徑失效；每小時重試
```

| 時段 | 行為 |
|---|---|
| 07:00–09:00 | 起床、前往工作地（`commuteMode`：mtr／bus／tram／ferry／walk） |
| 09:00–18:00 | 工作（working；建築不存在／未連通則重新求職） |
| 18:00–20:00 | 40% 購物、25% 消閒、其餘回家 |
| 20:00–24:00 | 在家；霓虹亮起；便利店 24 小時營業 |
| 00:00–07:00 | 睡眠，不移動（效能） |

- 通勤：`stats.avgCommute` 為全城平均（遊戲分鐘）；每日計算一次。
- 購物：`citizen.money -= 零售價（參考價 × RETAIL_PRICE_MULTIPLIER）`，`retail.incomeThisMonth += 同額`；貨架庫存已在每日結算扣除，購物不重複扣貨。
- 路徑失效 → `idle`，下一小時重試。

### 5.5 公屋輪候（UI 衍生指標，不需新增 state）

```
households          = ceil(stats.population / 3)
lowIncomeHouseholds = round(households × 0.45)
prhCapacity         = 公共屋邨數量 × 25        // 每座約 25 伙
waiting             = max(0, lowIncomeHouseholds − prhCapacity)
annualAllocation    = max(6, 公共屋邨數量 × 6)
waitYears           = clamp(waiting / annualAllocation, 1.5, 20)
```

- UI 頂欄／城事面板顯示「公屋輪候 N.N 年」；> 5 年 → 基層幸福 −3（`prhPenalty`）。
- 劏房居民比例 = `waiting > 0 ? min(0.35, waiting / lowIncomeHouseholds) : 0`；公屋足夠時劏房自然被取代。
- 政策（v1.1）：出售居屋、重建舊屋邨。

### 5.6 就業與通勤

- 職位 = 所有建築 `workers` 總和；16–64 歲市民自動求職，優先「離家近、通勤快」（30 格內）。
- 失業原因要可解釋：① 職位不足 → 「請建商廈／工廈」；② 未連路 → 「道路未接通」；③ 通勤 > 60 分鐘 → 市民拒絕上班。
- 缺工比例直接打折產量／服務；每棟建築 `workers.length > 0` 才營運。
- 月薪 $18,000；失業者靠積蓄，長期失業 → 幸福下降、遷出風險。

### 5.6.1 分區玩法下的人口輸入（給 citizens-dev）

分區系統的 RCI+F 需求直接讀取以下市民／人口數據，**定義要一致**：

| 需求輸入 | 來源 | 注意 |
|---|---|---|
| 職位空缺率 | `stats.jobs − stats.employed` | `jobs` = 所有建築 `workers` 總和（含自動建築） |
| 失業率 | `stats.unemployed / (employed + unemployed)` | 16–64 歲；失業者不交薪俸稅 |
| 無家率 | `stats.homeless / population` | 無家者優先入住自動住宅 |
| 住宅空置 | 住宅總容量 − 人口 | 容量含自動＋手動住宅 |
| 幸福 | `stats.happiness` | 影響需求與 devScore |
| 食品／日用品可撐日數 | `stats.foodStored / foodPerDay`、庫存 | 影響農業／工業需求 |

- 自動住宅落成後，人口系統照常遷入（無家者優先）；**不要**為分區另設「入伙」邏輯。
- 市民通勤模式、就業分配、幸福公式不變（見 §5.3–5.6）；分區只改變「住宅從哪裡來」。

### 6.3 通勤時間公式

```
roadDistance = 道路最短路徑格數（含隧道格）
tunnelPenalty = 過海隧道 +8 分鐘／次；跨山隧道 +5 分鐘／次
modeSpeed = 若住戶與工作地都在某站點半徑內（可多選，取最快）→ TRANSIT_SPEED[mode]
            否則 1（步行）
walkMinutes = roadDistance × 2.2 + tunnelPenalty
commuteMinutes = round(walkMinutes / modeSpeed) +（渡輪候船 5 分鐘）
上限 120 分鐘；> 60 分鐘 → 市民可能拒絕該工作
```

| 例子（無隧道） | 步行 | 巴士 ×2.2 | 渡輪 ×3.0 | 港鐵 ×4.2 |
|---|---|---|---|---|
| 10 格 | 22 分鐘 | 10 分鐘 | 12 分鐘 | 5 分鐘 |
| 30 格 | 66 分鐘 | 30 分鐘 | 27 分鐘 | 16 分鐘 |
| 過海 30 格（+8） | 74 分鐘 | 34 分鐘 | 25 分鐘 | 18 分鐘 |

> 設計目標：大部分市民通勤 15–35 分鐘；> 40 分鐘開始扣幸福；新界→九龍要壓到 40 分鐘內需巴士／港鐵（R-NT-1）。

### 6.4 車費收入

```
對每座營運中的交通站點：
  staffing = clamp(workers.length / def.workers, 0, 1)
  covered  = 站點半徑內住宅人口
  潛在乘客 = min(def.transit.capacity, covered × 2)      // 每人每日來回 2 程
  實際乘客 = round(潛在乘客 × staffing × transitWeather)
  transitWeather = WEATHER_EFFECT[weather].transit        // 0.35（颱風）～1
  ── 8 號風球：渡輪 suspended（0）、電車 0、巴士 ×0.5、港鐵 ×0.7
  車費收入／日 = 實際乘客 × def.transit.fare
```

- 車費收入每日計入 `building.incomeThisMonth`，月底併入 `finance.incomeBreakdown.fares`；`TransitState.faresThisMonth` 同步累計。
- 站點亦提供可達性：半徑內住宅地價 +10～20%（§2.2 地價加成）。
- 港鐵站造價高（$4M）、維護貴（$40k/月）→ 需要高人口（覆蓋人口 ×2 ≥ 容量）才回本；適合過海與新界—九龍走廊。

## 7. 財政系統

### 7.1 設計原則

- 庫房決定「能不能建」；真正壓力來自土地、勞動力、交通、天氣與幸福。
- 收入與支出分類以 `types.ts` 的 `IncomeKind`／`ExpenseKind` 為準：
  - 收入：`salaryTax`（薪俸稅）／`profitTax`（利得稅）／`rates`（差餉）／`landSale`（賣地）／`fares`（車費）／`service`（服務收入）／`other`。
  - 支出：`upkeep`（維護）／`civilService`（公務員薪酬）／`welfare`（福利）／`infrastructure`（基建）／`festival`（煙花）／`other`。
- 稅制「簡單低稅」：三條滑桿（薪俸稅／利得稅／差餉）＋一次性賣地（R-TAX-1）。

### 7.2 收入公式（`finance.ts`）

```ts
const D = DAYS_PER_MONTH;                 // 7
const salaryTax = stats.employed * finance.salaryTaxRate * BASE_MONTHLY_SALARY;
// 例：90 人就業 × 15% × $18,000 = $243,000／月

const profitBase = Σ(b => ['commercial','industrial','logistics'].includes(BUILDINGS[b.key].category)
                        ? BUILDINGS[b.key].cost * 0.05 : 0);   // 每月應評稅利潤（遊戲簡化）
const profitTax = profitBase * finance.profitTaxRate;
// 例：12 座工商建築平均 $1.5M → profitBase=$900,000 ×16.5% = $148,500／月

const rateable = Σ(b => BUILDINGS[b.key].cost);   // 應課差餉租值（遊戲簡化＝造價）
const rates = rateable * finance.ratesRate / 12;
// 例：20 座平均 $1M → $20M ×5% ÷12 = $83,333／月

const fares = Σ(交通站點：實際乘客 × fare × D)；         // 見 §6.4
const service = Σ(零售／餐飲：incomePerDay × D × util)； // util = staffing × 有貨率
const landSale = 賣地次數 × LAND_SALE_AMOUNT；           // $2,500,000／次

income = salaryTax + profitTax + rates + fares + service + landSale + other;
finance.treasury += income - operating;   // operating = totalUpkeep(buildings)
```

- 所有收入在月底 `monthlyFinance` 一次入賬，並寫入 `finance.incomeBreakdown`／`MonthRecord.incomeByKind`。
- 建造費、賣地、煙花即時加減 treasury，亦記入 `expenseThisMonth`／`incomeThisMonth`；月底報表不重複扣（沿用舊版做法）。

### 7.3 支出公式

```ts
const operating = totalUpkeep(buildings);                        // 建築維護（月底）
const civilService = stats.population * 300                        // 公務員薪酬：人口 × $300
                   + publicServiceWorkers * 1_000;                // 學校／醫院／警署／消防局工人 × $1,000
const welfare = seniors * 600 + stats.unemployed * 1_000;         // 長者＋失業
const infrastructure = 0;                                          // ROAD_UPKEEP=0；v1.1 加道路維護
const festival = 舉辦煙花當日 FESTIVAL_COST ($800,000)            // 即時扣
```

### 7.4 稅率滑桿（以 config 為準）

| 滑桿 | 範圍 | 預設 | 影響 | 民心懲罰 |
|---|---|---|---|---|
| 薪俸稅 `salaryTaxRate` | 0–20%（步進 1%） | **15%** | 就業人口 | 每 1% → −0.3 幸福（15% → −4.5） |
| 利得稅 `profitTaxRate` | 0–25%（步進 1%） | **16.5%** | 工商物流利潤 | 每 1% → −0.1 幸福（16.5% → −1.65） |
| 差餉 `ratesRate` | 0–12%（步進 0.5%） | **5%** | 所有物業 | 每 1% → −0.2 幸福（5% → −1.0） |

- 甜蜜點：薪俸 12–16%、利得 14–18%、差餉 4–6%；加稅前先看服務是否足夠。
- UI 要顯示「預估月收入」即時變化（±10% 可接受）。

### 7.5 賣地（香港特色）

- 操作：財政面板／建造工具「賣地」→ 按 `sellLand()`。
- 收入：每次 `LAND_SALE_AMOUNT = $2,500,000`，記入 `finance.incomeBreakdown.landSale`，`finance.landSales++`，`finance.lastLandSaleDay = totalDays`。
- 冷卻：**15 日**（`LAND_SALE_COOLDOWN_DAYS`）；每局建議上限 **24 幅**（設計值，UI 顯示剩餘）。
- 代價：每次賣地後 10 日內幸福 −2（樓價上升／土地減少）；公屋土地減少 → 輪候 +0.2 年（v1.1）。
- 與現實對應：香港政府收入中賣地與補地價是重要且波動的來源（R-LAND-1）；本作把它做成「即時現金 vs 長期土地」的取捨。

### 7.6 維港煙花匯演（節慶）

- 操作：財政面板「舉辦煙花匯演」；成本 **$800,000**（`FESTIVAL_COST`），冷卻 **20 日**（`FESTIVAL_COOLDOWN_DAYS`）。
- 效果：全體幸福 +12（12 日內線性衰減）；觀光收入 ×1.5（當日）；寫 log。
- 只在庫房 ≥ $800,000 時可按；不足 → 按鈕 disabled＋tooltip。

### 7.7 月報表

- `finance.history` 保留 24 個月；UI 顯示最近 8 個月。
- 欄位：年月、收入（7 類）、支出（6 類）、盈餘、人口、幸福。
- 月報表下方「本月大事」：賣地、煙花、颱風、人口里程碑（來自 `state.log`）。

### 7.8 破產與貸款

- `treasury < 0`：不可建新建築（可拆遷退款）；UI 紅框「庫房見底」；幸福 −5（`bankruptcyPen`）。
- 連續 2 個月虧損 → 財政面板警告「結構性赤字」。
- 🕒 v1.1 貸款：借 $20,000,000、月息 1.5%、24 個月還清；破產 3 個月 → 遊戲結束（可讀檔）。

| 冬 `winter` | 12–2 月 | 寒潮 | 16°C | 0.70 | 清涼、乾燥、山頂結霜 | 冬藏、長者健康、煙花 |

- `seasonOfMonth`：3–5 春、6–8 夏、9–11 秋、12–2 冬（config）。
- 季節切換 toast：「回南天，牆身出水」「盛夏酷熱，記得開冷氣」「秋高氣爽，好日子」「寒潮將至，問候長者」。

### 8.4 天氣（6 種，以 `WEATHER_WEIGHTS`／`WEATHER_EFFECT` 為準）

| 天氣 | 春 | 夏 | 秋 | 冬 | 農業 | 移動 | 幸福 | 交通 | 電力需求 |
|---|---|---|---|---|---|---|---|---|---|
| 晴 `clear` | 18 | 30 | 52 | 38 | 1.05 | 1.0 | +2 | 1.0 | 1.00 |
| 陰 `cloudy` | 27 | 18 | 25 | 32 | 1.0 | 1.0 | 0 | 1.0 | 1.02 |
| 雨 `rain` | 30 | 30 | 12 | 12 | 1.2 | 0.8 | −1 | 0.9 | 1.05 |
| 颱風 `storm` | 5 | 20 | 5 | 0 | 0.2 | 0.35 | −8 | 0.35 | 1.18 |
| 霧 `fog` | 20 | 2 | 6 | 10 | 1.0 | 0.7 | −2 | 0.75 | 1.03 |
| 雪 `snow` | 0 | 0 | 0 | 8 | 0.4 | 0.5 | −6 | 0.5 | 1.12 |

> 天氣 key 是 **`storm`（颱風）**，不是 `typhoon`；`Weather` 型別已定稿為 `clear | cloudy | rain | storm | fog | snow`。`snow` 在冬季代表寒潮／大帽山結霜（平地雨夾雪）。

### 8.5 天文台警告（`clock.warning` 與 `stats.typhoonSignal`）

| 警告 | 觸發（設計） | 效果 |
|---|---|---|
| **1 號風球** | `weather='storm'` 且 `typhoonSignal=1`（強度 < 0.5） | 預警；觀光 −20% |
| **3 號風球** | `typhoonSignal=3`（強度 0.5–0.8） | 學校停課；渡輪減班；農業搶收 |
| **8 號風球** | `typhoonSignal=8`（強度 > 0.8） | 停工停課；渡輪停航、電車停駛、港鐵露天段停駛、地盤停工；物流 ×0.35；幸福 −8（已含 weather） |
| 黃／紅／黑雨 | `weather='rain'` 且 `weatherIntensity` 0.4–0.6／0.6–0.8／>0.8 | 黑雨：物流 ×0.4、低窪水浸、山泥傾瀉風險 |
| 酷熱 | 夏季、晴、`tempC ≥ 33` | 生產效率 −10%、電力需求 +25%、火災風險 +50% |
| 寒冷 | 冬季、`tempC ≤ 10` | 長者死亡風險 ×1.5、農業 −20%（已含季節） |
| 大霧 | `weather='fog'` | 渡輪 50% 停航、山頂纜車（v1.1）停駛 |

- `TYPHOON_SIGNALS = [1, 3, 8]`（config；**沒有 9／10 號**，v1 不做）。
- `clock.warning` 顯示文字（如「八號東北烈風或暴風信號」）；UI 另以 `stats.typhoonSignal` 上色。
- 8 號風球每年上限 **4 次**（設計值，economy-dev 控管），避免隨機破壞過密。

### 8.6 天氣持續時間與強度（建議 `time.ts` 常數）

- 天氣持續：`duration = (600 + rng×600) × (0.8 + rng×0.4)` 遊戲分鐘（約 8～20 遊戲小時）；颱風固定 480–900 分（4–7.5 小時）。
- `weatherIntensity` 每 40 遊戲分平滑更新；颱風強度 0.3 → 0.9 線性升降（接近／遠離）。
- 氣溫每 60 遊戲分平滑；`tempC = 季節基礎 + 日夜正弦（±4°C）+ 天氣修正（晴 +2、陰 −1、雨 −2、霧 −1、雪 −4、颱風 −3）`。
- 季節切換時，若天氣不合理（如夏季雪）→ 重擲。

4. 人物：低多邊形人偶或剪影，數量依實際人數（上限 8 個，其餘用名單）。
5. 香港質感：鐵閘、鋁窗、晾衫竹、卡位、水吧、點心車、貨𨋢、霓虹燈管、紅白藍帆布、唐樓地磚、電錶、板間牆。

## 10. UI／UX 概要

### 10.1 資訊層級原則

1. **永遠可見**（頂欄）：城市名、日期、季節天氣、警告信號、庫房 `$`、人口、幸福、公屋輪候、速度、面板入口。
2. **常駐輔助**：左側建造面板（7 分類）、右側城事面板（概況／選取建築）。
3. **按需彈出**：財政、交通、存檔、說明／教學、警告詳情。
4. **即時回饋**：toast、建造幽靈、原因 chips、資源庫存。
5. **不打擾**：toast 最多 5 則、3.2 秒淡出；modal 開啟時模擬不暫停（玩家可自行暫停）。
6. **原因優先**：任何紅色數字旁都要有短原因（缺路、缺電、缺水、缺貨、通勤太遠、稅太重、颱風）。

## 13. 數值平衡與 config 建議（600 真實地理）

### 13.1 平衡總原則

1. **需求是油門、devScore 是門檻**：需求夠但 devScore 低 → 只出低級樓；devScore 高但需求負 → 唔會起樓。
2. **分區成本要痛但唔致命**：$700–$1,500/格；10×10 住宅區 $120,000（開局 $8M 的 1.5%），600 地圖可劃大片但要留意後續公共設施開支。
3. **自動建築每日 15 棟、每區 6 棟、全城上限 1,200**：面積約 10 倍，開發速率同步放大；高密度實測約 152 棟，上限預留擴充。
4. **公共設施是關鍵投資**：警／消／校／醫／電／水直接把 devScore 由 31 推到 75–100。
5. **大地圖需要導航**：minimap（600 真實地形）＋O 全圖／P 市中心是必需品；empty 完全空地圖要靠玩家自己建立地標感。
6. **真實地理限制**：可建地只有 22.4%、水域 75.6%；山多平地少係設計壓力，唔可以再要求 worldgen「補到 52% 可建」。

## 附錄 C：核心資料流（分區版）

```
[玩家輸入] --GameActions--> main.ts
  ├─ setTool/applyToolAt --> placement.ts
  │     ├─ 'road'：鋪馬路（自帶 sidewalk）
  │     ├─ 'zone:xxx'：刷分區（扣 $700–$1,500/格）
  │     ├─ 'dezone'：清分區（免費）
  │     └─ 'demolish'／建築 key：拆除（退 30%）／手動置建築
  ├─ sellLand／holdFestival／setTaxRate --> finance
  ├─ save/load/newGame --> core/save.ts（v6 compact：seed＋sparse tileEdits）、core/new-game.ts（starter／empty）
  └─ focusTile/fitMap --> store.emit('focus') --> CityView（minimap 點擊／O／P）

[每幀] Simulation.update(state, dt, ctx)
  ├─ advanceClock（time.ts）
  │    ├─ newDay --> updateConnectedBuildings
  │    │              + tickProduction（4 資源、公用設施、carts）
  │    │              + tickZoning（新：需求 → devScore → 自動開發／荒廢）
  │    │              + tickTransit（ridership、fares、颱風停航停駛）
  │    │              + tickPopulation（遷入／死亡／就業／需求／幸福）
  │    │              + tickLogistics（貨車、零售補貨）
  │    ├─ newMonth --> monthlyFinance（7 收入、6 支出、月報表）
  │    └─ newYear --> 事件（v1.1）
  ├─ tickCitizens（移動、購物、狀態機）
  ├─ tickLogistics（貨車移動）
  ├─ updateStats（每幀 O(n)；zoneTiles／zoneBuildings／landValue 每日）
  └─ CityView.frame()：environment → terrain → roads → zones → buildings → vehicles → citizens
  └─ ui.update(state)（diff：需求條、分區供需、發展商動態）

[分區資料]
  Tile.zone（4 種；null＝未分區）
  Building.auto／zone（自動開發來源）
  GameState.zoneDemand（−1..1，4 區）
  GameStats.zoneTiles／zoneBuildings／policeCoverage／fireCoverage／schoolCoverage／hospitalCoverage／landValue

[UI 讀取]
  stats（人口／就業／食品／幸福／覆蓋率／zoneDemand／landValue）
  finance（treasury / 稅率 / incomeBreakdown / expenseBreakdown）
  transit（dailyRidership / faresThisMonth / suspended / byMode）
  clock（日期／天氣／warning／季節）
  buildings（auto／zone／connected／workers／residents／inventory）
  log（最近 3 條＋發展商動態）
```
